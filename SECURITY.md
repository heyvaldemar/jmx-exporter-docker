# Security Policy

## Supported versions

| Tags | Status |
|---|---|
| `1.7.0`, `1.7`, `1` and `latest` | :white_check_mark: rebuilt every week |

Fixes ship in the next build; nothing is patched in place. A build that still carries a critical or high finding with a fixed version is not published (`scripts/cve-gate.sh`).

## Reporting a vulnerability

Report privately through GitHub: **Security → Report a vulnerability** on this repository (private vulnerability reporting is enabled). Email to v@valdemar.ai also works. The process is described at [heyvaldemar.com/security](https://heyvaldemar.com/security/).

You can expect an acknowledgment within 7 days. This project does not operate a bounty program; researchers who submit valid, responsibly disclosed reports receive public credit in the release notes and the changelog.

Please do not open public GitHub issues for security reports. A vulnerability in the exporter itself belongs to [prometheus/jmx_exporter](https://github.com/prometheus/jmx_exporter/security); one in OpenJDK or another Debian package, to Debian.

## Supply chain verification

Every published image digest is signed with cosign using Sigstore keyless OIDC issued to this repository's GitHub Actions workflow. SBOM (SPDX, generated by BuildKit) and SLSA build provenance are attached to every image, and build provenance is attested in GitHub Attestations. jmx_exporter is built from source at a pinned commit, and every Maven artifact the build resolves is checked against the SHA-512 recorded in `maven/`.

```bash
cosign verify heyvaldemar/jmx-exporter:1 \
  --certificate-identity-regexp "https://github.com/heyvaldemar/jmx-exporter-docker/.*" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com"
```

## Credentials

The repository holds no credentials. Publishing uses the `DOCKERHUB_USERNAME` and `DOCKERHUB_TOKEN` repository secrets; signing is keyless.
